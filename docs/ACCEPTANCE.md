# Повторная приёмка «Разгрома» по работам 1–4
24 ноября 2026 г. Версия 2.0, Python 3.12. Критерии взяты из четырёх отчётов в этой папке. ПР4 описывает прежнее состояние программы. Ниже зафиксированы результаты проверки текущей реализации.

## ЛР1. Пользовательский сценарий и границы MVP
Приложение предназначено для личного планирования на одном устройстве. При запуске открывается выбранная по системной дате страница «Сегодня». Для быстрого ввода достаточно открыть форму, ввести название и сохранить. Дата и средний приоритет уже установлены. Задачи располагаются в приватной SQLite, регистрация отсутствует. В итоговом манифесте проверены разрешения: уведомления, точные сигналы и загрузка системы. Разрешение INTERNET отсутствует.

## ПР3. Архитектурные решения
Сохранились автономная работа, разделение экранов, хранилища и логики уведомлений, SQLite и системный планировщик. Технологический выбор изменён по заданию на перенос: Flutter/Dart заменены Python, Chaquopy и Android SDK. В APK включён тот же TaskRepository, который используют тесты. Телефонные настройки используются Android-адаптером. При загрузке ОС расписание восстанавливает BroadcastReceiver.

Выборка дня по 5000 записям заняла в среднем 0,11 мс на компьютере (100 вызовов, порог 50 мс). Измерение относится к запросу в SQLite. Для критерия «экран быстрее 1 с» требуется отдельно измерить отображение на целевых смартфонах.

## ПР4. Тестирование, дефекты и CI
TC-01–TC-08 соответствуют восьми тестам исходной регрессии. Все прошли. Для QA-01 и QA-02 добавлены проверки корректности даты и времени до INSERT и UPDATE. TC-09 и TC-10 теперь проходят. При отклонённом изменении сохраняется исходное значение. Корректны 23:59 и високосная дата 29.02.2028. Дополнительные тесты проверяют завершение, удаление и обработку старой повреждённой записи при планировании остальных задач. Всего 12 из 12 тестовых методов прошли локально. Порог для готовности устройства остаётся отдельным критерием.

## Организационная приёмка
Настройку защиты ветки, одобрение макетов и тест-кейсов обоими участниками, взаимный code review и очную демонстрацию отмечают участники команды. В журнал TST-03 нужны фактические результаты с двух телефонов: модель, версия Android, разрешения, назначенное и фактическое время, отмена и перенос. Это также проверяет различия в энергосбережении производителей.
